# ГЛУБИНА

Браузерный 3D-рогалик от первого лица: спуск на пять этажей подземелья.
Изображение прогоняется через ретро-фильтр в духе Lethal Company — низкое
внутреннее разрешение, дизеринг, зерно, строчная развёртка, хроматические
аберрации и плотный туман.

Чистый JavaScript (ES-модули) + WebGL2. Без игровых движков, без библиотек,
без npm-зависимостей, без шага сборки. Все текстуры, модели и звуки
генерируются кодом при запуске — в проекте нет ни одного файла ассетов.

Если ты садишься за проект и хочешь знать, в каком он состоянии, по каким
правилам его трогать и что делать дальше — читай **[HANDOFF.md](HANDOFF.md)**.
Здесь описано устройство, там — работа.

## Как запустить

ES-модули не грузятся по `file://` (браузеры применяют к ним CORS), поэтому
нужен любой статический сервер:

```bash
python3 -m http.server 8000
# затем открой http://localhost:8000/
```

Годится что угодно: `npx serve`, `php -S localhost:8000`, «Live Server» в
VS Code. Нужен браузер с WebGL 2.0 (Chrome/Edge/Firefox/Safari 15+).

## Управление

| | |
|---|---|
| `WASD` | движение |
| мышь | обзор (щёлкни по окну, чтобы захватить курсор) |
| `ЛКМ` | стрелять |
| `Shift` | бежать (тратит выносливость и шумит) |
| `Ctrl` / `C` | присесть (тихо и медленно) |
| `F` | фонарь вкл/выкл |
| `E` | взять / купить / спуститься |
| `Q` | активный предмет |
| `Tab` / `M` | карта |
| `Esc` | пауза и меню |
| `R` | начать спуск заново (с подтверждением) |
| `F11` | полный экран |
| `` ` `` | отладочный оверлей |

В меню: стрелки или `WASD` — выбор, `←` `→` — значение, `Enter` — ок,
`Esc` — назад. Мышь тоже работает: наведение подсвечивает строку, щелчок
выбирает.

Геймпад: левый стик — ход, правый — обзор, RT — огонь, RB — фонарь,
A — подтвердить, B — назад, X — взаимодействие, Y — предмет, Start — пауза.
Крестовина и левый стик водят по меню.

Телефон и планшет: палец в левой части экрана — стик движения (кольцо
появляется там, где ты его поставил), палец в правой — обзор. Кнопки по
краям: `ОГОНЬ`, `ВЗЯТЬ`, `ПРЕДМЕТ`, `ФАКЕЛ`, переключатели `БЕГ` и `СЕСТЬ`
слева, `КАРТА`, полный экран и пауза сверху. В меню кнопки прячутся — там
достаточно тапнуть по строке. Экранные кнопки появляются только после
первого касания, так что на десктопе их нет.

## Что внутри

**Пять этажей**, у каждого своя палитра, свои монстры, свой босс и своя
настройка фильтра:

1. **Заросшие верха** — почти поверхность, зелень и жёлтые лампы. Босс: Леший.
2. **Синие пустоты** — глубже, бирюзовое биолюминесцентное свечение и ямы.
   Босс: Хироптера, мать стаи.
3. **Магмовые кузни** — жарко, оранжевые угли, но лавы ещё нет.
   Босс: Мехокузнец.
4. **Лавовое озеро** — теперь лава, и она занимает почти весь пол.
   Босс: Игнарок.
5. **Призматическая сокровищница** — яркий разноцветный этаж: шесть
   насыщенных источников света, кристаллы, золото. Босс: Хромадракон.

**Механики**

- **Фонарь и батарея.** Батарея садится всё время, пока горит фонарь.
  Без света почти ничего не видно, но и монстры замечают тебя хуже.
  Батареи разбросаны по этажу и продаются в лавке — это главный ресурс,
  задающий темп спуска.
- **Шум и зрение.** Монстры должны тебя *заметить*: у них есть конус зрения,
  проверка прямой видимости и слух. Шум зависит от того, что ты делаешь:
  стоять на месте — 0.12, красться — 0.27, идти — 1.07, бежать — 2.71,
  стрелять — минимум 1.9. Быть незамеченным — это состояние, которым можно
  пользоваться.
- **Перегрев вместо патронов.** Ствол остывает только через 0.4 секунды после
  последнего выстрела, поэтому непрерывная стрельба глохнет примерно через
  четыре секунды и стоит четверти времени. Прицельная стрельба очередями
  перегрева почти не замечает.
- **Выносливость** на бег.
- **Здоровье растёт.** Каждый убитый хозяин этажа даёт +2 к максимуму и
  полностью лечит. Аптечки лечат долю от максимума, а не фиксированные три
  единицы, и не подбираются, пока здоровье полное, — их можно оставить
  лежать и вернуться. Вне боя раны затягиваются сами, но только до половины.
- **Территория опасна по-разному.** У каждого этажа своя опасная поверхность:
  заросли первого этажа держат сильнее, чем ранят, лава четвёртого — наоборот.
  Первое мгновение в луже всегда бесплатное.
- **Предметы комбинируются.** Модификаторы выстрела складываются в одном
  конвейере, поэтому «наведение + расщепление + взрыв» работает само собой.
  Отдельно прописаны именованные связки (напалм, рельсотрон, чума, чёрная
  дыра и другие) — они меняют поведение, а не только цифры. Броня врагов
  срезает не больше трёх четвертей удара, чтобы сборки из множества мелких
  снарядов не обнулялись об одного бронированного монстра.

**Сложность**

Три уровня, прямо на титульном экране: «спокойный», «обычный», «глубокий».
Крутятся три честные ручки, а не одна «здоровье врагов ×2»: насколько сильно
бьёт подземелье, сколько оно держит и с каким запасом начинает игрок.
Выбранный уровень показан на паузе и в итогах забега, чтобы результаты можно
было сравнивать.

**Меню**

Титульный экран, пауза, настройки (сложность, сила фильтра, яркость,
дрожание вершин, громкость по трём шинам, чувствительность мыши, инверсия
по Y), справка по управлению и подтверждения на перезапуск и выход.
Настройки сохраняются. Экраны смерти и победы — тоже меню, а не одна
подсказка «нажми Enter».

## Структура кода

```
index.html            точка входа
styles.css            только оформление страницы
src/
  main.js             оболочка: связывает платформу, ядро и рендер
  core/               ЧИСТАЯ ЛОГИКА — никаких браузерных API
    constants.js  math3.js  rng.js  events.js  loop.js
    game.js           оркестратор забега
    combat.js         снаряды и урон
    world/            генерация подземелья, рельеф, контур пещер, коллизии
    entities/         игрок, монстры, пул снарядов
    ai/behaviors.js   16 поведений монстров
    items/            инвентарь, статы, конвейер выстрела
    bosses/           по файлу на босса
    ui/menu.js        меню: экраны, строки, навигация — без единого DOM-вызова
  data/               ВСЕ ДАННЫЕ ИГРЫ, редактируются без правки движка
    floors.js  enemies.js  items.js  synergies.js
    gear.js           редкость, оружие, реликвии
    decor.js          стили комнат и таблицы обстановки
    floors.js  enemies.js  items.js  synergies.js  difficulty.js
    creature-art.js  sounds.js  sprite-ids.js
  gfx/                презентация (WebGL2)
    gl.js  shaders.js  renderer.js
    textures.js       процедурные текстуры
    meshbuild.js      геометрия уровня + примитивы
    creatures.js      меши монстров из описаний
    hud.js            интерфейс
  platform/           СЛОЙ-АДАПТЕР
    interfaces.js     контракт платформы
    browser/          реализация для браузера
tools/bot.mjs         головой-бот: играет забеги без браузера
tools/smoketest.mjs   проверки (только для разработки)
```

Правило слоёв: `src/core` и `src/data` не знают ни про `window`, ни про
`document`, ни про `localStorage`, ни про WebGL, ни про Web Audio. Побочные
эффекты уходят через шину событий (`sfx`, `fx`, `shake`, `floorStart`,
`uiCommand`, …), а обратно приходит только нейтральный снимок ввода.

Меню подчиняется тому же правилу: `core/ui/menu.js` — это стек экранов из
типизированных строк и правила навигации. Он не знает ни про клавиши, ни про
канвас. HUD спрашивает, что рисовать, и возвращает обратно прямоугольники
нарисованных строк, чтобы клик попадал ровно туда, куда игрок целится; всё,
что должно дотянуться до платформы — полный экран, выход в меню, сохранение —
уезжает событием `uiCommand`, а расшифровывает его оболочка.

## Как добавлять контент

- **Монстр** — строка в `src/data/enemies.js` + описание тела в
  `src/data/creature-art.js`. Поведение берётся из готового набора в
  `core/ai/behaviors.js`.
- **Предмет** — строка в `src/data/items.js`. `stats` — прибавки,
  `mult` — множители, `flags` — модификаторы выстрела, `hooks` — реакции
  на события.
- **Связка** — строка в `src/data/synergies.js`.
- **Оружие** — строка в `WEAPONS` (`src/data/gear.js`). `stats` здесь
  *заменяют* базовые, а не прибавляются: оружие — это не бонус, а то, что
  у тебя в руках. `art` задаёт вид модели (длина ствола, массивность, цвет
  ядра), поэтому новое оружие сразу выглядит иначе.
- **Реликвия** — строка в `RELICS` там же плюс строка в `BOSS_RELIC`.
  Правило: реликвия меняет правило, а не число. Если её можно записать как
  «+15% урона» — это предмет, а не реликвия.
- **Этаж** — строка в `src/data/floors.js` + босс в `core/bosses/`.
  Количество этажей нигде в движке не зашито.
- **Стиль комнаты** — строка в `STYLES` (`src/data/decor.js`): какая кладка,
  какой пол, какой потолок, какой оттенок. Дальше остаётся добавить имя стиля
  в `styles` нужного этажа.
- **Обстановка** — строка в таблице `scatter` этажа: `kind` из списка,
  который понимает `gfx/meshbuild.js`, `weight` — как часто, `glow`/`color` —
  светится ли. Плотность этажа задают `density` здесь и `scatter` в
  `floors.js`, рельеф — `relief` там же.

Правило для новой обстановки: она не участвует в коллизиях. Либо ниже
шага, либо выше головы, либо прижата к стене, куда игрок всё равно не
дотянется. Единственное, что действительно перекрывает проход, — клетка
`C.PILLAR`, потому что она есть в самой сетке.
- **Уровень сложности** — строка в `src/data/difficulty.js`; меню подхватит
  её само.

## Настройка фильтра

Всё в `post` каждого этажа (`src/data/floors.js`):

| параметр | что делает |
|---|---|
| `levels` | сколько уровней на канал остаётся после квантования |
| `grain` | зерно |
| `scanline` | строчная развёртка |
| `aberration` | хроматическая аберрация по радиусу |
| `vignette` | виньетка |
| `saturation` / `contrast` / `brightness` / `tint` | цветокоррекция |

Глобально силу фильтра можно приглушить через `game.settings.filterStrength`
(0 — почти чистая картинка, 1 — как задумано) и `game.settings.wobble`
(дрожание вершин в духе PS1).

## Сборка десктопной версии

Архитектура к этому готова: вся игровая логика в `src/core`, всё, что зависит
от платформы, — в `src/platform`. Для ПК-сборки нужно:

### Tauri (маленький бинарник, системный webview)

1. `npm create tauri-app` либо добавить `src-tauri/` в этот репозиторий
   вручную.
2. В `tauri.conf.json` указать `"frontendDist": "../"`, `devUrl` — на
   локальный сервер. Отдельной сборки фронтенда не нужно: отдаются те же
   `index.html` и `src/`.
3. Пути относительные, внешних запросов нет, поэтому CSP можно оставить
   строгой: `default-src 'self'`.
4. **Заменить адаптеры** в `src/platform/`:
   - `storage-browser.js` → сохранения в файл через
     `@tauri-apps/plugin-fs`; интерфейс тот же (`load` / `save` / `remove`).
   - `display-browser.js` → полный экран через окно Tauri
     (`appWindow.setFullscreen`) вместо `requestFullscreen`.
   - `input-browser.js` → захват курсора Tauri (`setCursorGrab`,
     `setCursorVisible`) вместо Pointer Lock; плюс `setLockWanted`, чтобы
     меню отпускало курсор. Остальное не меняется.
   - `audio-browser.js` можно оставить: Web Audio в webview доступен.
5. Собрать `src/platform/tauri/platform-tauri.js` по образцу
   `platform-browser.js` и передать его в `boot()` — сейчас `boot()` сам
   создаёт браузерную платформу, вынести это в параметр это одна строка.

### Electron

1. `npm i -D electron`, минимальный `main.js` с
   `new BrowserWindow({ webPreferences: { contextIsolation: true } })` и
   `win.loadFile('index.html')`.
2. Адаптеры: хранилище — на `app.getPath('userData')` через IPC, полный
   экран — `win.setFullScreen`. Pointer Lock в Electron работает, так что
   `input-browser.js` подойдёт как есть.
3. Упаковка — `electron-builder`.

### Что уже сделано ради десктопа

- фиксированный шаг симуляции, отвязанный от частоты кадров;
- вся логика без обращений к `window` / `document` / `localStorage`;
- контракт платформы с проверкой (`assertPlatform`) — неполный адаптер
  падает сразу и с понятным сообщением;
- меню и настройки живут в ядре: порт получает их бесплатно и только
  расшифровывает события `uiCommand` по-своему (у десктопа, например,
  появляется «Выход»);
- относительные пути, ноль сетевых запросов, ноль внешних файлов;
- внутреннее разрешение рендера не зависит от размера окна.

## Разработка

```bash
node tools/smoketest.mjs                        # обе части, ~1 минута
node tools/smoketest.mjs --core-only            # без браузера, ~25 секунд
node tools/smoketest.mjs --quick                # меньше прогонов
node tools/smoketest.mjs --seconds 60 --shots   # дольше + скриншоты
node tools/smoketest.mjs --headed               # с видимым окном
node tools/gallery.mjs                          # витрина скриншотов
```

**Ядро** гоняется прямо в Node — `src/core` и `src/data` не зависят от
браузера, поэтому можно позволить себе проверять всерьёз: 300 этажей на
проходимость и на то, что лестница действительно вырезана в сетке; повтор
генерации по сиду байт в байт; 40 забегов ботом на софтлоки; каждый предмет
и каждая активка по отдельности и все разом; каждая пассивная связка
переживает пересчёт статов; все девять экранов меню обходятся, ползунки
упираются в границы, `Esc` разматывает стек; каждый босс — девять боёв
против бессмертного игрока; шестьдесят полных забегов сводятся в кривую
сложности с ограничителями с обеих сторон.

`gallery.mjs` обходит игру и снимает её целиком: каждый этаж в каждом типе
комнат, все монстры этажа в ряд, каждый босс в двух фазах. Удобно, когда
надо посмотреть, что сделало изменение со всей игрой, не проходя пять
этажей руками. Результат по умолчанию в `/tmp/deepshade-gallery`,
каталог задаётся через `--out`.

Playwright нужен только для этих двух скриптов; сама игра зависимостей
не имеет.
**Браузер** ловит любую ошибку консоли, исключение и упавший запрос, водит
забег через настоящий слой ввода и обходит всё меню клавиатурой и мышью,
проверяя, что настройки доезжают до адаптеров звука и ввода, а захват
курсора отпускается на паузе и возвращается при продолжении.

`tools/bot.mjs` — тот самый бот: он играет обычными снимками ввода, той же
формы, что отдаёт браузерный адаптер. Он намеренно средний игрок — не
уворачивается от пуль и не кайтит, — поэтому измеренные им числа это нижняя
граница, а не верхняя.

Playwright нужен только для браузерной части; сама игра зависимостей
не имеет. Без него прогоняется одно ядро.

## Производительность

Сцена всегда рисуется в буфер 428×240 независимо от размера окна, поэтому
нагрузка почти не зависит от разрешения экрана — растёт только стоимость
финального растяжения. Уровень — один статический меш, монстры дальше
50 метров не обновляются, снаряды и частицы лежат в пулах без аллокаций,
источников света не больше двенадцати за кадр.

В headless-прогоне на программном растеризаторе (SwiftShader, без GPU)
шаг симуляции укладывается в 0.7 мс, отрисовка — в 6.6 мс на кадр; на любой
настоящей видеокарте это с большим запасом укладывается в 60 FPS.
