# ГЛУБИНА

Браузерный 3D-рогалик от первого лица: спуск на пять этажей подземелья.
Изображение прогоняется через ретро-фильтр в духе Lethal Company — низкое
внутреннее разрешение, дизеринг, зерно, строчная развёртка, хроматические
аберрации и плотный туман.

Чистый JavaScript (ES-модули) + WebGL2. Без игровых движков, без библиотек,
без npm-зависимостей, без шага сборки. Все текстуры, модели и звуки
генерируются кодом при запуске — в проекте нет ни одного файла ассетов.

---

## Как запустить

ES-модули не грузятся по `file://` (браузеры применяют к ним CORS), поэтому
нужен любой статический сервер:

```bash
python3 -m http.server 8000
# затем открой http://localhost:8000/
```

Годится что угодно: `npx serve`, `php -S localhost:8000`, «Live Server» в
VS Code. Нужен браузер с WebGL 2.0 (Chrome/Edge/Firefox/Safari 15+).

## Что внутри

**Пять этажей**, у каждого своя палитра, свои монстры, свой босс и своя
настройка фильтра:

1. **Заросшие верха** — почти поверхность, зелень и жёлтые лампы. Босс: Леший.
2. **Синие пустоты** — глубже, бирюзовое биолюминесцентное свечение и ямы.
   Босс: Хироптера, мать стаи.
3. **Магмовые кузни** — жарко, оранжевые угли, но лавы ещё нет.
   Босс: Мехокузнец.
4. **Лавовое озеро** — теперь лава, и она занимает почти весь пол.
   Босс: Игнарок.
5. **Призматическая сокровищница** — яркий разноцветный этаж: шесть
   насыщенных источников света, кристаллы, золото. Босс: Хромадракон.

**Механики**

- **Фонарь и батарея.** Батарея садится всё время, пока горит фонарь.
  Без света почти ничего не видно, но и монстры замечают тебя хуже.
  Батареи разбросаны по этажу и продаются в лавке — это главный ресурс,
  задающий темп спуска.
- **Шум и зрение.** Монстры должны тебя *заметить*: у них есть конус зрения,
  проверка прямой видимости и слух. Бег и стрельба слышно далеко, приседание —
  почти нет. Быть незамеченным — это состояние, которым можно пользоваться.
- **Перегрев вместо патронов.** Оружие греется; на пределе оно глохнет,
  пока не остынет.
- **Выносливость** на бег.
- **Предметы комбинируются.** Модификаторы выстрела складываются в одном
  конвейере, поэтому «наведение + расщепление + взрыв» работает само собой.
  Отдельно прописаны именованные связки (напалм, рельсотрон, чума, чёрная
  дыра и другие) — они меняют поведение, а не только цифры.

## Структура кода

```
index.html            точка входа
styles.css            только оформление страницы
src/
  main.js             оболочка: связывает платформу, ядро и рендер
  core/               ЧИСТАЯ ЛОГИКА — никаких браузерных API
    constants.js  math3.js  rng.js  events.js  loop.js
    game.js           оркестратор забега
    combat.js         снаряды и урон
    world/            генерация подземелья, рельеф, коллизии, навигация
    entities/         игрок, монстры, пул снарядов
    ai/behaviors.js   16 поведений монстров
    items/            инвентарь, статы, конвейер выстрела
    bosses/           по файлу на босса
  data/               ВСЕ ДАННЫЕ ИГРЫ, редактируются без правки движка
    floors.js  enemies.js  items.js  synergies.js
    decor.js          стили комнат и таблицы обстановки
    creature-art.js  sounds.js  sprite-ids.js
  gfx/                презентация (WebGL2)
    gl.js  shaders.js  renderer.js
    textures.js       процедурные текстуры
    meshbuild.js      геометрия уровня + примитивы
    creatures.js      меши монстров из описаний
    hud.js            интерфейс
  platform/           СЛОЙ-АДАПТЕР
    interfaces.js     контракт платформы
    browser/          реализация для браузера
tools/smoketest.mjs   headless-проверка (только для разработки)
```

Правило слоёв: `src/core` и `src/data` не знают ни про `window`, ни про
`document`, ни про `localStorage`, ни про WebGL, ни про Web Audio. Побочные
эффекты уходят через шину событий (`sfx`, `fx`, `shake`, `floorStart`, …),
а обратно приходит только нейтральный снимок ввода.

## Как добавлять контент

- **Монстр** — строка в `src/data/enemies.js` + описание тела в
  `src/data/creature-art.js`. Поведение берётся из готового набора в
  `core/ai/behaviors.js`.
- **Предмет** — строка в `src/data/items.js`. `stats` — прибавки,
  `mult` — множители, `flags` — модификаторы выстрела, `hooks` — реакции
  на события.
- **Связка** — строка в `src/data/synergies.js`.
- **Этаж** — строка в `src/data/floors.js` + босс в `core/bosses/`.
  Количество этажей нигде в движке не зашито.
- **Стиль комнаты** — строка в `STYLES` (`src/data/decor.js`): какая кладка,
  какой пол, какой потолок, какой оттенок. Дальше остаётся добавить имя стиля
  в `styles` нужного этажа.
- **Обстановка** — строка в таблице `scatter` этажа: `kind` из списка,
  который понимает `gfx/meshbuild.js`, `weight` — как часто, `glow`/`color` —
  светится ли. Плотность этажа задают `density` здесь и `scatter` в
  `floors.js`, рельеф — `relief` там же.

Правило для новой обстановки: она не участвует в коллизиях. Либо ниже
шага, либо выше головы, либо прижата к стене, куда игрок всё равно не
дотянется. Единственное, что действительно перекрывает проход, — клетка
`C.PILLAR`, потому что она есть в самой сетке.

## Настройка фильтра

Всё в `post` каждого этажа (`src/data/floors.js`):

| параметр | что делает |
|---|---|
| `levels` | сколько уровней на канал остаётся после квантования |
| `grain` | зерно |
| `scanline` | строчная развёртка |
| `aberration` | хроматическая аберрация по радиусу |
| `vignette` | виньетка |
| `saturation` / `contrast` / `brightness` / `tint` | цветокоррекция |

Глобально силу фильтра можно приглушить через `game.settings.filterStrength`
(0 — почти чистая картинка, 1 — как задумано) и `game.settings.wobble`
(дрожание вершин в духе PS1).

## Сборка десктопной версии

Архитектура к этому готова: вся игровая логика в `src/core`, всё, что зависит
от платформы, — в `src/platform`. Для ПК-сборки нужно:

### Tauri (маленький бинарник, системный webview)

1. `npm create tauri-app` либо добавить `src-tauri/` в этот репозиторий
   вручную.
2. В `tauri.conf.json` указать `"frontendDist": "../"`, `devUrl` — на
   локальный сервер. Отдельной сборки фронтенда не нужно: отдаются те же
   `index.html` и `src/`.
3. Пути относительные, внешних запросов нет, поэтому CSP можно оставить
   строгой: `default-src 'self'`.
4. **Заменить адаптеры** в `src/platform/`:
   - `storage-browser.js` → сохранения в файл через
     `@tauri-apps/plugin-fs`; интерфейс тот же (`load` / `save` / `remove`).
   - `display-browser.js` → полный экран через окно Tauri
     (`appWindow.setFullscreen`) вместо `requestFullscreen`.
   - `input-browser.js` → захват курсора Tauri (`setCursorGrab`,
     `setCursorVisible`) вместо Pointer Lock; остальное не меняется.
   - `audio-browser.js` можно оставить: Web Audio в webview доступен.
5. Собрать `src/platform/tauri/platform-tauri.js` по образцу
   `platform-browser.js` и передать его в `boot()` — сейчас `boot()` сам
   создаёт браузерную платформу, вынести это в параметр это одна строка.

### Electron

1. `npm i -D electron`, минимальный `main.js` с
   `new BrowserWindow({ webPreferences: { contextIsolation: true } })` и
   `win.loadFile('index.html')`.
2. Адаптеры: хранилище — на `app.getPath('userData')` через IPC, полный
   экран — `win.setFullScreen`. Pointer Lock в Electron работает, так что
   `input-browser.js` подойдёт как есть.
3. Упаковка — `electron-builder`.

### Что уже сделано ради десктопа

- фиксированный шаг симуляции, отвязанный от частоты кадров;
- вся логика без обращений к `window` / `document` / `localStorage`;
- контракт платформы с проверкой (`assertPlatform`) — неполный адаптер
  падает сразу и с понятным сообщением;
- относительные пути, ноль сетевых запросов, ноль внешних файлов;
- внутреннее разрешение рендера не зависит от размера окна.

## Разработка

```bash
node tools/smoketest.mjs                        # headless-прогон
node tools/smoketest.mjs --seconds 60 --shots   # дольше + скриншоты
node tools/smoketest.mjs --headed               # с видимым окном
```

Тест поднимает статический сервер, грузит игру в headless Chromium, ловит
любые ошибки консоли и исключения, гоняет автопилот через настоящий слой
ввода, а затем прогоняет симуляцию без рендера: генерация всех этажей на
десяти сидах, бой с каждым боссом до убийства, каждый предмет и активка
по отдельности и все предметы разом.

Playwright нужен только для теста; сама игра зависимостей не имеет.

## Производительность

Сцена всегда рисуется в буфер 428×240 независимо от размера окна, поэтому
нагрузка почти не зависит от разрешения экрана — растёт только стоимость
финального растяжения. Уровень — один статический меш, монстры дальше
50 метров не обновляются, снаряды и частицы лежат в пулах без аллокаций,
источников света не больше двенадцати за кадр.

В headless-прогоне на программном растеризаторе (SwiftShader, без GPU)
шаг симуляции укладывается в 0.7 мс, отрисовка — в 6.6 мс на кадр; на любой
настоящей видеокарте это с большим запасом укладывается в 60 FPS.
