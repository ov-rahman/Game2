# Инструкция по проекту

Что это, в каком оно состоянии, по каким правилам его трогать, что уже
сделано, что делается сейчас и что осталось.

`README.md` отвечает на вопрос «как это устроено и как добавить контент».
Этот файл отвечает на вопрос «что делать дальше и как не сломать».
`CHANGELOG.md` — история по версиям.

## 1. Состояние

| | |
|---|---|
| версия | 0.4.0 |
| ветка разработки | `claude/roguelike-dungeon-game-debj6r` |
| стадия | ранняя бета |
| запускается | да, консоль чистая |
| smoke-тест | зелёный |
| зависимости | ноль (Playwright — только для теста) |

Что это значит на практике: весь заявленный контент на месте и работает —
пять этажей, 31 тип монстров (по 5–6 в таблице каждого этажа плюс элиты и
приспешники), 5 боссов по три фазы у каждого, 52 предмета, 15 именованных
связок, 6 стволов, 6 реликвий, 46 звуков, 18 поведений ИИ. Генерация, бой,
предметы, боссы и фильтр проверяются автотестом на каждой итерации.

Чего ещё нет: игру ни разу не прошёл живой игрок от начала до конца.
Баланс между этажами не проверен ничем, кроме здравого смысла. Меню
настроек нет. Звук работает, но на слух его никто не оценивал.

**Правило номер один: в репозитории всегда лежит работающая версия.**
Ветка не может быть сломанной ни на одном коммите.

## 2. Первые пять минут

```bash
# запустить
python3 -m http.server 8000     # и открыть http://localhost:8000/

# проверить, что ничего не сломано (главная команда, ~2 минуты)
node tools/smoketest.mjs

# то же, но дольше и со скриншотами кадров автопилота
node tools/smoketest.mjs --seconds 60 --shots

# витрина: по 3–4 кадра на каждый этаж, все монстры, все боссы
node tools/gallery.mjs            # результат в /tmp/deepshade-gallery
```

Так выглядит зелёный прогон — если что-то из этих строк пропало или
изменилось в меньшую сторону, значит, сломали:

```
core sim        50 floor generations across 10 seeds
bosses          ЛЕШИЙ✓(p3) ХИРОПТЕРА✓(p3) МЕХОКУЗНЕЦ✓(p3) ИГНАРОК✓(p3) ХРОМАДРАКОН✓(p3)
items           52 exercised
lights          3660 checked, all finite
gear            6 weapons, 6 relics, 5/5 boss drops
all-items run   ok (15 synergies active)
clean: no console errors, no exceptions.
```

Строчка `played to floor 1, kills 2` — это про автопилот, а не про игру:
он не умеет стрелять (см. раздел 5). Низкий FPS в отчёте тоже нормален:
тест идёт на программном растеризаторе без видеокарты; смотреть надо на
`worst sim step` и `draw`.

В игре: `` ` `` — отладочный оверлей (FPS, время шага, время кадра,
координаты, число сущностей). `Tab` — карта. `Esc` — пауза.

Из консоли браузера доступен `window.__DEEPSHADE__`:

```js
const g = __DEEPSHADE__.game;
g.startRun(12345);        // забег с конкретным сидом
g.nextFloor();            // сразу вниз
g.player.hp = 99;
g.enemies.length = 0;     // очистить этаж
g.torch.charge = 1;
__DEEPSHADE__.loop.fps;   // и .stepMs / .renderMs
```

Это же используют `smoketest.mjs` и `gallery.mjs` — там готовые примеры
того, как поставить игрока в нужную комнату, выдать босса или выстроить
монстров в ряд для скриншота.

## 3. Правила, которые нельзя нарушать

Они не стилистические — на каждом из них держится что-то конкретное.

1. **Ноль зависимостей, ноль шага сборки, ноль файлов-ассетов.**
   Всё — текстуры, модели, звуки — генерируется кодом при запуске.
   Если появляется соблазн подключить библиотеку или положить `.png` —
   это ошибка, а не компромисс.

2. **`src/core` и `src/data` не знают про браузер.** Ни `window`, ни
   `document`, ни `localStorage`, ни WebGL, ни Web Audio. Всё это живёт
   в `src/platform/`. Логика получает нейтральный снимок ввода и отдаёт
   события наружу. Ради этого написан контракт `interfaces.js` с проверкой
   `assertPlatform` — неполный адаптер падает сразу и понятно. Это то, что
   позволит собрать десктопную версию, не переписывая игру.

3. **Фиксированный шаг симуляции.** Логика идёт с постоянным dt, рендер —
   с интерполяцией. Не привязывать поведение к частоте кадров.

4. **Рельеф — один источник правды.** Высота пола в точке — только
   `groundAt(terrain, x, z)` из `core/world/terrain.js`. Её же читает
   построение меша, её же читает игрок и монстры. Если рендер начнёт
   считать высоту по-своему, персонажи поедут сквозь пол — и это будет не
   видно на скриншоте, а только ногами.

5. **Обстановка не участвует в коллизиях.** Любой новый камешек, гриб или
   лиана должны быть либо ниже шага, либо выше головы, либо прижаты к
   стене. Единственное, что реально перекрывает проход, — клетка
   `C.PILLAR`, потому что она есть в самой сетке.

6. **Контент — это данные.** Новый монстр, предмет, ствол, этаж или стиль
   комнаты добавляются строкой в `src/data/`, без правки движка. Если для
   нового монстра пришлось трогать `core` — скорее всего, не хватает
   поведения в `ai/behaviors.js`, а не частного случая.

7. **После каждой заметной итерации:** прогнать `smoketest.mjs`, дописать
   `CHANGELOG.md`, закоммитить. Не копить.

## 4. Что уже сделано

Крупными мазками, в порядке коммитов:

| коммит | что |
|---|---|
| `8737ca7` | 2D-прототип: ядро, пять этажей, боссы, предметы (заменён) |
| `7810fd4` | переработка в 3D от первого лица, WebGL2, фильтр в духе Lethal Company |
| `9ce5ff1` | документация, план десктопной сборки, changelog |
| `6a8021d` | свет, обратная связь по урону, лава — чтобы картинка читалась |
| `ca39d41` | своя кладка у каждой комнаты, низкополигональная обстановка |
| `69b5c24` | читаемый интерфейс сквозь фильтр |
| `efacd3c` | рельеф: подклеточные неровности, обрывы, контурные пещеры |
| `4e43287` | трава, лианы, ручьи из стен, лагеря, руины |
| `dfc3783` | оружие, реликвии, редкость, сундуки, тайные каморки |
| `08a14bb` | щели в стенах закрыты, пол смешивается вместо плитки, починен NaN в свете |
| `78a5462` | шесть разных силуэтов оружия вместо одного серого ящика |

Из неочевидного, что стоит знать, прежде чем что-то менять:

- **Пол не плиточный.** Высота = билинейная выборка по угловой сетке
  (GRID_W+1)×(GRID_H+1) плюс fBm-детализация, умноженная на пер-угловую
  «шероховатость». Каждая клетка режется на 2–3 подчетырёхугольника, у
  каждого своя из восьми диэдральных ориентаций UV, и поверх этого идёт
  смешивание двух материалов по плавному полю — поэтому переходы между
  породами не видны как сетка. Вершина весит 15 флоатов: позиция, нормаль,
  UV, второе UV, вес смешивания.
- **Стены пещер строятся по изолинии** (marching squares, SUB=4) по
  размытому и зашумлённому полю открытости. Поле предварительно
  **расширяется** (dilation), чтобы изолиния уехала на сторону камня —
  иначе сеточная коллизия перестанет совпадать с тем, что видно.
- **Вертикальность** держится на типе клетки `C.LEDGE` (парапет: блокирует
  как стена, но рисуется низким бортиком) и на ограничителе уклона, у
  которого два исключения — закреплённые углы комнат и обрывы, у которых
  обе соседние клетки каменные.
- **Связность гарантируется после декорирования**, а не до: заливка →
  откат планов комнат → в крайнем случае `digTo`. Проверено на 1120
  комнатах в 100 подземельях, недостижимых нет.
- **HUD рисуется в 2D-канву и вклеивается внутрь пост-обработки**, но
  фильтр над ним приглушён маской `hudMask` — иначе текст съедает
  дизеринг. Не выносить HUD наружу: он должен быть частью картинки.
- **Оружие рисуется своей проекцией** (24°, дистанция 1.5), иначе ствол
  разъезжается по краям экрана. После него обязательно восстанавливается
  `uViewProj`.
- **Оружие заменяет базовые статы, а не прибавляет.** Реликвии оперируют
  флагами, а не числами.

## 5. Что делается сейчас

**Бот, который реально проходит забег.** Существующий автопилот в
`smoketest.mjs` ходит и жмёт мышь, но браузерный адаптер принимает выстрел
только при захваченном курсоре, а захвата в headless нет — поэтому за
прогон у него два убийства и первый этаж. Тест проверяет, что ничего не
падает; что в игру можно играть, он не проверяет.

Что с этим делать:

1. Повесить огонь на клавишу в браузерном адаптере ввода (или подавать
   `input.down.fire` напрямую в снимок — снимок для того и нейтральный).
2. Дать боту простую цель: ближайший непосещённый узел `NavField`,
   стрелять по ближайшему видимому монстру, `E` на всём, что подсвечено.
3. Критерий успеха: пять этажей за прогон, все боссы убиты, ни одной
   ошибки в консоли.
4. И только после этого — снимать с него метрики баланса (см. ниже).

## 6. Что осталось

### P0 — без этого нет беты

- **Баланс по этажам.** Мерять, а не угадывать. Когда бот проходит забег,
  собрать: время на этаж, урон, полученный игроком, число смертей на
  каждом боссе, средний запас батареи на спуске. Крутить `floors.js`
  (бюджет спавна, `scatter`, `relief`) и `enemies.js` (hp, скорость,
  урон), пока кривая не станет возрастающей и без провалов на 3-м этаже.
- **Обратная связь по попаданиям.** Проверить на глаз, что каждое попадание
  видно и слышно: вспышка на монстре, отдача, звук, число урона. Сейчас
  это есть, но никто не смотрел, читается ли оно в бою на пятом этаже,
  где на экране двадцать источников света.
- **Смерть и перезапуск.** Экран смерти есть; проверить, что после
  `Enter` начинается чистый забег и ничего не утекает между забегами
  (`enemies`, `props`, `dynamicLights`, `exploredCells`, пулы).

### P1 — нужно для «игры», а не «демо»

- **Меню настроек.** Данные уже есть — `game.settings`:
  `filterStrength` (0…1), `brightness`, `wobble`, `sensitivity`.
  Не хватает только экрана: список, стрелки, сохранение через
  `platform.storage`. Плюс громкость — вывести общий множитель в
  аудио-адаптер.
- **Сохранения.** Адаптер `storage-browser.js` работает; надо решить, что
  именно сохраняем. Минимум — рекорды и настройки. Сохранение забега
  посреди этажа не обязательно и потянет за собой сериализацию всего мира.
- **Геймпад.** Раскладка описана в README и реализована, но её не проверяли
  живым геймпадом. Проверить мёртвые зоны стиков и что триггер жмётся как
  кнопка огня.
- **Звук на слух.** 46 процедурных звуков сгенерированы и вызываются;
  никто не слушал, не режет ли ухо и не теряется ли попадание в общем шуме.

### P2 — качество

- **Критик.** Прогнать отдельным агентом сравнение с Isaac / Gungeon /
  Hades / Dead Cells: что в этих играх делает бой приятным и чего у нас
  нет. Первая попытка сорвалась по лимиту, задача осталась.
- **`standalone.html`.** `index.html` при открытии по `file://` советует
  открыть `standalone.html` — а его в репозитории нет. Либо собрать
  однофайловую сборку (склеить модули в один инлайновый скрипт — шага
  сборки это не потребует, достаточно скрипта в `tools/`), либо убрать
  упоминание.
- **Десктопная сборка.** План расписан в README (Tauri или Electron).
  Единственная правка в самой игре — вынести создание платформы из `boot()`
  в параметр, это одна строка.

### P3 — если будет время

- **Настоящий второй ярус** над той же точкой XZ. В текущем представлении
  (одна клетка = одна колонка) это невозможно; потребуются слоистые
  клетки — большая переделка `dungeongen`, `collision` и `meshbuild`.
  Сейчас перепад высот отыгрывается террасами, провалами и парапетами.
- Больше связок предметов; сейчас именованных 15, а комбинаторика
  позволяет больше.

## 8. Грабли

Всё это уже случалось. Если картинка сломалась — сначала сюда.

**Одна NaN-координата у источника света гасит весь свет.** Причина была в
`pr.h`, не заданной у части декораций, — `light.y` становился NaN, и сцена
чернела целиком, без единой ошибки в консоли. Теперь `uploadLights`
проверяет x/y/z/radius/intensity/r/g/b, а тест считает все 3660 источников
на конечность. Если экран внезапно чёрный — проверять свет, а не шейдеры.

**Порядок обхода вершин.** `box`, `prism`, `blob` когда-то были написаны
под другую намотку и рисовали задние грани — модели выглядели вывернутыми
наизнанку. Новый примитив всегда проверять на модели, которую видно.

**Транспонирование UV нельзя делать глобально.** Один раз поменяли местами
u и v целиком и стали попадать в незакрашенные слоты атласа — пол покрылся
пурпурными квадратами. Транспонировать можно только внутри прямоугольника
плитки.

**Смещение вершин нельзя сеять индексом сегмента.** Наклон стен пещер
задавался по номеру сегмента, и два соседних сегмента двигали общую точку
в разные стороны — в стенах появлялись вертикальные щели, сквозь которые
видно уровень. Смещение должно зависеть **от позиции**: `leanOffset(x, z, …)`.

**Лава — не кристалл.** Опасности сначала рисовались тем же мешем, что и
светящиеся кристаллы, и выжигали кадр. У жидкостей отдельный меш примерно
с третью свечения.

**`prism` строится вдоль +Y.** Для стволов нужен `tubeZ` (вдоль +Z), иначе
оружие смотрит в потолок.

**Виджет вида оружия нуждается в своей проекции.** С общей матрицей ствол
шатается по краям экрана.

**Текст под фильтром нечитаем**, если не приглушить над ним квантование,
зерно и виньетку. Позиции — только целые пиксели, у текста обводка и
подложка.

**Как искать регрессию:** сделать worktree на заведомо рабочий коммит
(`git worktree add /tmp/prev <sha>`), поднять оба на разных портах и
сравнивать скриншоты, откатывая по одному файлу. Так нашёлся чёрный экран.

## 9. Чеклист перед коммитом

1. `node tools/smoketest.mjs` — зелёный, консоль чистая.
2. Игра открывается в браузере и в неё можно играть руками.
3. `CHANGELOG.md` дополнен.
4. Ни одной новой зависимости, ни одного файла-ассета, ни одного обращения
   к `window` / `document` / `localStorage` из `core` или `data`.
5. Коммит осмысленным сообщением в
   `claude/roguelike-dungeon-game-debj6r`.
